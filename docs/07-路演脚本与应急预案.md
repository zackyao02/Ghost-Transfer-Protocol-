# 路演脚本与应急预案

## 1. 四分钟路演

### 0:00～0:30：钩子

“多数生成式游戏每次只是生成一个新角色。我们想知道：如果这个角色记得自己被怎样对待，甚至能换一具身体，它还是一次性内容吗？”

### 0:30～1:00：身体进入世界

- 玩家张掌唤醒机械神龛。
- 展示实时手部轮廓、动作进度与 Ghost 核心。
- 一句话说明 Python MediaPipe 与 Unity 的低延迟输入链路。

### 1:00～2:00：手势战斗

- 横划释放剑诀，击败石精。
- 画圈生成净化符，开启记忆祭坛。
- 展示 Agent：读取记忆 → 形成意图 → 调用世界工具。

### 2:00～3:00：反转与高潮

- 山魈出现，揭示其体内是上一位玩家留下的 Ghost。
- Ghost 根据历史选择挡伤或背叛。
- 张掌触发神降法相和收容扫描。

### 3:00～3:35：持续世界证明

- 玩家选择封存、共生或换壳。
- 重启或载入下一局，展示场景伤痕、义体和阵营变化。
- 切换第二个评审存档，证明相同关卡会产生不同结果。

### 3:35～4:00：收束

“我们生成的不是一具模型，而是一个会记忆、会换壳、甚至可能背叛你的数字生命。”

## 2. 应急等级

### A：完整模式

- 摄像头、Python、Agent 和 Tripo 展示全部正常。
- 完成全视觉交互和真实 Agent 决策。

### B：守护辅助模式

- 手势能追踪但识别不稳定。
- 放宽动作阈值，轨迹完成 70% 后自动补全。
- Agent 使用缓存结果，保持监控面板演示。

### C：导演模式

- 摄像头或 Python 不可用。
- 演示者用隐藏键盘触发同一技能和动画。
- UI 只显示“灵官辅助校准”，不展示技术错误。

### D：视频与存档模式

- Unity 构建异常或现场设备不可控。
- 播放完整备用视频，同时用两个评审存档说明持续世界。

## 3. 故障处理

| 故障 | 现场处理 |
|---|---|
| 摄像头被占用 | 切导演模式，不重启整场演示 |
| Python 断线 | 1 秒内提示辅助接管，键盘继续 |
| Agent 超时 | 使用当前存档缓存决策 |
| Tripo 网络失败 | 使用三套预生成义体 |
| 帧率下降 | 关闭雨、远景粒子和次要后处理 |
| 手势连续失败 | 降低阈值并启用轨迹自动补全 |
| Unity 崩溃 | 切备用构建或演示视频 |

## 4. 评委问答

### 这是不是硬编码剧情？

关卡边界和工具是规则化的，但 Agent 根据 Ghost 记忆、关系和战况选择意图及工具组合。监控面板会展示真实输入、决策和结果；评审存档用于保证演示可复现。

### Tripo 是否只是换皮？

不是。义体类型映射到防御、速度、攻击和可用行为，Agent 选择不同义体会改变 Boss 和下一局能力。

### 为什么使用 Unity？

Unity 能稳定承载 3D 场景、角色、灯光、VFX 和 Windows 离线构建，同时通过本地 Python 服务获得手势关键点，不把游戏主循环绑定到识别耗时。

### 如果摄像头或网络失败怎么办？

所有输入都进入同一个技能接口，键盘导演模式能触发完全相同的玩法和演出；Agent 与 Tripo 都有本地缓存和预生成回退。
